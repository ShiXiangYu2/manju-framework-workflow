# S6 · 门禁、机检规则与交付

> 挂载阶段：S6 `/框架交付`｜出口：`05-handoff.md` + `framework-check.txt` + G6

## 1. Gate 判据（人工核对动作）

| Gate | 核对动作 | 不通过的自查顺序 |
|---|---|---|
| G0 | 打开情报卡，逐项勾：入口类型 / 播放面 / 已读范围 / 不可改事实 / 禁区 / 对标样本或「纯原创」 | 先补情报，别在 S1 用想象填 |
| G1 | 念契约给第三人听；看流派是否与 S3 单元链一致；终止条件是否可核对 | 契约带集号 → 回 S1 重写 |
| G2 | 数方向候选是否 ≥2 且机制不同；「明确拒绝的方向」是否写了 | 只有 1 个候选 → 补机制差异 |
| G3 | 打开单元链表，验覆盖、硬帽、三缝合一说明、付费墙落位 | 单元 >30 集 → 拆；墙不在接缝 → 移墙或调单元边界 |
| G4 | 打开节拍表，随机抽 3 集问「本集结算了什么、又欠下什么」；看相邻集承接 | 说不清 → 回 S3 重拆单元，别改正文 |
| G5 | 四账逐表看是否有空表头；伏笔是否有拟收集团；漫剧不变量是否单列 | 伏笔无回收计划 → 补，否则下游必烂尾 |
| G6 | 跑机检、清占位符、写交接单 | 有 FAIL 不交付；WARN 逐条写复核结论 |

**判断框架是否成立的一句话标准**：随机抽一集，不看前后文也能说清「本集结算了什么、又欠下什么」。说不清就是单元链没拆干净，回 S3，别急着写正文。

### 付费墙有两套定义，别混用（方法冲突说明）

两个源仓库在这件事上 genuinely 对不上：

| | 商业首墙 | 结构墙 |
|---|---|---|
| 来源 | `0xsline/short-drama`：免费转付费的转化窗口 | `short-drama-factory`：付费墙挂单元接缝 |
| 位置 | 第 8–12 集（长档 4–6 集） | 每个单元止集 ±1 集 |
| 目的 | 沉没成本足够、悬念未解时收钱 | 换矛盾处天然是情绪峰值与攻守转换点 |

60 集三单元时第一道接缝在 EP20，与 EP10 的商业首墙必然不重合。本包**两类都保留**：商业首墙单独填在「商业首墙集号」列并豁免接缝规则，结构墙填在「结构墙集号」列且必须挂接缝；两类合并后统一检查卡点间隔 ≥5 集。硬把两者合成一条规则会逼用户造假数据。

## 2. F01–F18 机检规则

| 编号 | 级别 | 检查对象 | 判据 |
|---|---|---|---|
| F01 | FAIL | `output/` | 6 个交付文件齐全 |
| F02 | FAIL | 简报 | 12 个必填字段齐全：情绪契约/流派/终止条件/档位/总集数/单集时长/播放面/套路/开场/故事型/赛道/画风 |
| F03 | FAIL | 契约 | 单句、8–60 字、不含「第N集 / EP\d+」等集号 |
| F04 | FAIL | 流派 | ∈ {情绪流, 剧情流} |
| F05 | FAIL | 档位 | 集数 ∈ {30,40,50,60,80,100}；长档对应 30/40/50；漫剧档时长 60–90 秒且字数 330–620 |
| F06 | FAIL | 单元链 | 单元数 2–4 |
| F07 | FAIL | 单元链 | 每单元 12–30 集（长档 6–15 集） |
| F08 | FAIL | 单元链 | 起止连续覆盖 1..总集数，无缺口、无重叠 |
| F09 | FAIL | 单元链 | 每个非末单元「换矛说明」非空（三缝合一）；每单元有可核对的循环终止条件 |
| F10 | FAIL | 单元链 + 节拍表 | **结构墙**落在某单元接缝 ±1 集；节拍表付费墙标记与单元链声明一致（商业首墙豁免本条） |
| F11 | WARN | 单元链 | **商业首墙**（两类墙中集号最小者）落在 8–12 集（长档 4–6 集） |
| F12 | FAIL | 单元链 | 全部墙（商业 + 结构）相邻间隔 ≥5 集（长档 ≥3 集） |
| F13 | FAIL | 节拍表 | 行数 = 总集数，集号 1..N 连续 |
| F14 | FAIL | 节拍表 | 每行「进入状态/当集结算/新债/出去状态/钩子类型」非空 |
| F15 | WARN | 节拍表 | 相邻集「出去状态」与下一集「进入状态」有承接（关键词重合） |
| F16 | WARN | 节拍表 | 四段占比偏差 ≤5%（起势 15 / 攀升 30 / 风暴 35 / 决战 20） |
| F17 | FAIL | 台账 | 四账齐备；每条伏笔有首现集/拟收集团/状态，且回收间隔 ≥2 集 |
| F18 | FAIL | 全部 md | 无 `【填写】` / `TODO` / `TBD` 残留 |

**三级语义**：`FAIL` 必须修；`WARN` 人工复核并在机检报告写结论；`NOTE` 不要求修改。

## 3. 命令

```bash
python scripts/validate_framework.py --dir output       # 检查项目产出
python scripts/validate_framework.py --dir examples     # 检查随包样例
python scripts/validate_framework.py --selftest         # 规则自测（含反例注入）
python scripts/validate_framework.py --dir output --json # 机器可读结果
```

报告写到 `--dir` 下的 `framework-check.txt`。

## 4. 与下游机检的分工（不互相替代）

| 层 | 工具 | 查什么 |
|---|---|---|
| 框架层（本包） | `validate_framework.py` F01–F18 | 契约、单元链、节拍表、台账、占位符 |
| 正文层 | `short-drama-factory/scripts/validate_episode.py` E1–E26 | 体量、气口、断章、对白占比、无效微动作 E26、谜语黑话 E25、干聊断层 E24 |
| 全剧层 | `short-drama-factory/scripts/validate_series.py` S1–S8 | 伏笔超期、死人开口、断章缺失、付费墙落位、四表齐全、反转轮换 |
| 内容质量 | `drama-skills/evaluations/content_quality_gate.py` | 盲评式内容质量门禁 |

框架机检通过 ≠ 正文能看。三层都要跑。
